## 원본 양식 4장 검증 항목과 제출 증빙

아래 항목은 제공된 과제 양식의 **검증 장(4.1~4.8)**을 이 프로젝트의 구현·증빙에 맞게 요약했다. `T01` 같은 번호는 [검증 결과표](검증결과.md)의 시험 번호다. 2026-10-21 시험 결과와 이후 코드 상태를 혼동하지 않도록 날짜를 나눴다.

| 양식 범위 | 실제로 확인할 질문 | 증빙과 판정 |
|---|---|---|
| **4.1 데이터·색인** F2001~F2002 | 항목 수와 메타데이터 색인 수가 맞는가? 항목 텍스트에 검색 속성이 있는가? 같은 설정으로 다시 색인해도 증가하지 않는가? | [T01~T02](검증결과.md), [두 컬렉션·manifest](PIPELINES.md#2-rag-준비-질문-전에-무엇을-색인하는가). 당시 100항목/221청크로 확인. |

| **4.8 제출 점검** | 필수 기능·화면 증거·설계·소스·검증표·셀프/상호 점검이 모였는가? | [검증 결과 3~4절](검증결과.md). **공식 셀프 체크리스트와 동료 상호 점검은 미완료**. 개발 도우미의 검토를 동료 점검으로 대체하지 않는다. |

## 검증 숫자를 읽는 법

- [검증 결과표](검증결과.md)는 **2026-10-21 Windows 환경의 당시 스냅샷**이다. 그 안의 100항목/221청크, 프론트 197개·백엔드 37개 테스트를 현재 총량처럼 옮겨 적지 않았다.
- 이후 2026-10-23 Mac에서 직전 코드 검사는 프론트 **957개**, 백엔드 **87개**, 타입 검사·빌드 통과를 기록했다. 이는 자동 테스트 결과이며 **실제 모델 응답의 품질이나 외부 공개 접속 검증이 아니다**.
- 2026-10-23 로컬 `/api/health` 확인에서는 `knowledge_items` **131건**, `reference_chunks` **308건**, `rag_status=pilot_ready`였다. 생성·임베딩 설정은 존재하지만 health의 `verified` 값은 `false`이므로 이번 확인만으로 실제 제공자 호출 성공을 주장하지 않는다. 질문 중 새 문서가 색인되면 청크 수는 달라질 수 있다.
- 공개 배포는 아직 검증되지 않았다. 로컬 게임은 서버 없이 동작하고, 코치·지식 탐색·게시판에는 백엔드가 필요하다.

플레이 링크는 배포 후 [프로젝트 첫 화면](../../README.md)에 추가한다.
