# InfraCoach — AI 코어 프로젝트 2회차 제출

**SUDO QUEST**는 브라우저의 가상 CLI로 인프라 장애를 조사·복구하는 게임이다. **InfraCoach**는 플레이어가 관찰한 내용과 출처가 기록된 문서를 근거로 다음 점검을 안내하는 RAG 코치다. 실제 시스템 명령은 실행하지 않는다.

![가상 장애 실습부터 결과 리포트까지의 시연](../assets/demo/main.gif)

## 서비스 흐름

![브라우저 가상 실습과 선택적으로 연결되는 FastAPI·Chroma·SQLite의 전체 흐름](../assets/pipelines/overview.svg)

게임의 상태·명령·복구 판정은 브라우저에서 처리된다. 지식 질문은 **검색어 추출 → 후보 문서 선별 → 필요한 절 수집·색인 → 근거 검색 → 답변·인용 검증**을 거친다. 게임 코치는 숨겨진 `faults`·정답·전체 `state` 없이 티켓, 연 힌트, 최근 명령과 출력만 받는다. 처리 단계와 코드 위치는 **[가상 CLI·RAG 파이프라인 도식 4장](PIPELINES.md)**에 정리했다. [코치 시연 GIF](../assets/demo/coach.gif)

## 요구사항 검증과 증빙

아래 표는 제공된 과제 양식 **4.1~4.8**에 맞춘 안내다. `T01`~`T23`의 실제 입력·결과·판정은 [검증 결과표](검증결과.md)에 있다. **필수 F2001~F2012와 선택한 심화 F2013·F2015는 원본 양식의 기능 확인 범위에서 실행·검증했다.** 결과표의 일부 `부분` 표시는 여러 실습·힌트 단계, 자체 응답 시간 목표처럼 과제보다 넓게 잡은 점검의 한계도 포함한다.

| 양식 | 확인한 내용 | 증빙 |
|---|---|---|
| **4.1 데이터·색인** F2001~F2002 | 항목 속성, 항목당 메타데이터 색인 1건, 재색인 건수 불변 | [T01~T02](검증결과.md) · [색인 구조](PIPELINES.md#2-rag-준비-질문-전에-무엇을-색인하는가) |
| **4.2 수집·선별** F2003~F2005 | 검색어 JSON, 후보 채택·제외, 자체 문서 포함, 반복 수집 방지, 청크 설정 비교 | [T03~T05](검증결과.md) · [청크 비교](청크_TopK_비교.md) |
| **4.3 답변·근거** F2006~F2008 | Top-k 비교, `retrieve → generate`, 메타데이터·외부 문서 구분, 보류와 인용 번호 검증 | [T06~T08](검증결과.md) · [답변 흐름](PIPELINES.md#3-rag-답변-검색어부터-근거-카드까지) |
| **4.4 기능·화면** F2009~F2012 | 항목별 대화 격리, 실습 기록·문서 인용 코치, 조건 탐색, 진행·오류 안내 | [T09~T12](검증결과.md) · [화면 증빙](화면증빙_F2009_F2012.md) |
| **4.5 선택 심화** F2013·F2015 | React/FastAPI 화면과 질문·답변·근거, RAG 유무 비교 | [T13~T14](검증결과.md) · [전후 비교](RAG_전후비교.md) |
| **4.6 품질 비교** | 동일한 대표 질문 9개로 정확성·근거·보류를 비교 | [RAG 전후 비교](RAG_전후비교.md) · [후속 24문항 평가](../infra-coach/22_RAG_근거_보강.md) |
| **4.7 비기능** NF2001~NF2007 | 지연·캐시·키 비노출·안전한 오류·모듈 분리·수집 예절·출처 기록 측정 | [T15~T21](검증결과.md) · [출처와 이용 조건](../DATA_SOURCES.md) |
| **4.8 제출 점검** | 요구사항·설계·소스·README·검증 결과·화면 자료는 연결됨. 작성된 셀프·동료 상호 체크리스트는 저장소에 없음 | [아래 제출물](#제출물) · [검증 결과 3~4절](검증결과.md) |

**건수 해석:** 원본의 항목 수 대조는 `knowledge_items`의 항목별 메타데이터 색인에 적용한다. 문서를 청킹한 별도 `reference_chunks` 수는 항목 수와 같을 필요가 없다. 2026-10-21 검증 당시 **100항목·221문서 청크**였고, 2026-10-23 로컬 health 확인에서는 **131항목·308문서 청크**였다.

**판정의 한계:** F2010 코치는 한 실습에서 실습 기록과 문서 근거를 함께 인용해 원본 4.4의 확인 기준을 충족했다. 다른 실습·힌트 단계는 추가 실측 범위다. 첫 질문 평균 **23.2~25.7초**는 자체 15초 목표를 넘었지만, 원본 NF2001에는 숫자 제한이 없다. NF2006·NF2007의 수집 식별 정보·이용 조건 대조에는 [결과표](검증결과.md)에 적은 확인 범위가 남는다. 후속 24문항 평가는 개발 도우미 채점이므로 사람 평가를 대신하지 않는다.

검증 결과표는 **2026-10-21 Windows 시험의 기록**이다. 이후 **2026-10-23 Mac 코드 검사**에서 프론트 957개·백엔드 87개 테스트와 타입 검사·빌드가 통과했다. 이 수치는 실제 모델 품질이나 공개 배포의 검증 결과가 아니다. `GET /api/health`의 제공자 `configured=true`도 실제 호출 검증(`verified=false`)을 뜻하지 않는다.

**제출 직전:** 원본 양식 4.8은 작성된 셀프·동료 상호 체크리스트를 요구한다. 현재 저장소에는 두 결과가 첨부되지 않았다. 담당자가 실제 수행 결과를 넣어야 4.8까지 완료라고 표시할 수 있다. 공개 플레이 링크는 배포 후 [프로젝트 README](../../README.md)에 추가한다.
