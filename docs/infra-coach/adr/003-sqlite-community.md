# 003. 게시판 저장소는 SQLite 한 파일

- **상황:** 커뮤니티 카페는 글·댓글·삭제 비밀번호(해시) 정도이고, 쓰는 사람이 스터디원 규모다. 별도 DB 서버를 두면 배포·백업·비용이 커진다.
- **결정:** 표준 라이브러리 `sqlite3`로 `backend/data/community.sqlite3` 한 파일에 둔다. 스키마는 버전 번호(현재 3)로 올리며 옛 파일을 고쳐 쓴다. 예시 글은 시드 스크립트로 넣고 뺄 수 있다.
- **버린 대안:** (1) PostgreSQL — 동시 쓰기에 강하지만 이 규모엔 과하고 런타임 의존성이 는다. (2) JSON 파일 — 동시 쓰기·검색·페이지 나누기를 직접 구현해야 한다. (3) Chroma에 같이 저장 — 벡터 DB는 게시판 트랜잭션에 맞지 않는다.
- **결과:** 의존성 0, 파일 하나 백업. 대가: 쓰기가 한 번에 하나라 사용자가 크게 늘면 바꿔야 하고, 배포 시 영구 디스크가 필요하다(19번 계획 P4).
- **근거:** `backend/app/community/store.py`, `schema.py`, `tests/test_community*.py`.
