# 화면 증빙 — F2009 항목별 질의응답 · F2012 진행 상태 및 안내

실행일: 2026-10-21 16시대 · 환경: Windows, React 개발 서버(Vite) + FastAPI, GMS gpt-6.1-sol / text-embedding-3-large, 색인 `data/chroma-v2`(지식 100 / 청크 221)

상태 표기: 통과 = 이번 실행에서 화면 또는 실제 요청으로 확인함. 미확인 = 실행하지 않음.

## 재현 방법

오류 상태는 사용 중인 서버(8000/5173)를 건드리지 않고 임시 서버로 만들었다. 설정은 `.claude/launch.json`에 있다.

| 상태 | 서버 설정 | 화면 |
|---|---|---|
| 키 없음 + 색인 없음 | `api-empty-nokey`: CHROMA_PATH=빈 임시 폴더, 생성·임베딩 URL을 키가 없는 주소로 지정(실제 요청 없음) | `dev-5174-to-8001`(5174 → 8001 프록시) |
| 색인 있음 + 키 없음 | `api-index-nokey`: 프로세스 안에서 GMS_KEY만 빈 값으로 지정 | 같은 5174 화면 |
| 정상 | `api`(8000) | `dev`(5173) |

## F2009 항목 선택 및 질의응답

브라우저에서 `fetch`를 감싸 실제로 보낸 `/api/chat` 요청 본문을 기록했다(디버깅 목적이며, 코드에는 넣지 않았다).

| 순서 | 동작 | 실제 요청의 history | 화면 | 상태 |
|---|---|---|---|---|
| 1 | ENOSPC 항목에서 질문 A1 | 0개 | ENOSPC 대화 1건 | 통과 |
| 2 | curl 28로 바꿔 질문 B1 | 0개(ENOSPC 대화가 섞이지 않음) | 전환 직후 curl 28 대화 0건 | 통과 |
| 3 | ENOSPC로 돌아와 후속 질문 A2 | 2개 = A1 질문·답변만(curl 내용 없음) | 이전 A1 대화가 그대로 유지됨 | 통과 |
| 4 | curl 28로 돌아와 B1을 다시 질문 | 0개(실패한 B1은 맥락에서 제외) | curl 28 대화만 표시, ENOSPC 대화 없음 | 통과 |

증빙: `evidence/F2009_01_item_isolation_curl28.jpg`. 단위 테스트는 `tests/chatHistory.test.ts` 3개다(항목 분리, 오류 턴 제외, 최근 5회 제한).

대화는 화면을 사용하는 동안만 보관한다(새로고침하면 사라짐). 과제 예시(영화별 대화 저장)와 같은 범위다. 영구 저장은 구현하지 않았다.

## 실행 중 관찰한 외부 오류

- B1(1차): `generation_request_failed`. 이때는 서버 진단 로그가 없어 원인을 확인하지 못했다. 직후 `scripts.check_providers --only generation`은 성공했다.
- A2(1차): `embedding_request_failed`. 새로 넣은 서버 로그에 `InternalServerError status=502`가 남았다. GMS 게이트웨이의 일시 오류다.
- 두 질문 모두 다시 보냈을 때 성공했다. 공급자 호출은 설계상 자동 재시도 0회이므로 사용자가 다시 시도해야 한다. 5xx에 한해 1회 재시도를 넣을지는 결정이 필요하다.
- 이번에 바꾼 점: 공급자 실패 시 서버 로그에 예외 종류와 HTTP 상태만 남긴다(키·메시지 제외, 테스트로 확인).

## 미확인

- 공식 셀프 체크리스트 양식은 아직 받지 않았다.
- 화면 폭이 좁을 때(모바일)의 안내 배치는 따로 캡처하지 않았다.
