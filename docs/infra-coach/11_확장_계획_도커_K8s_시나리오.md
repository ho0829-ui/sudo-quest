# 확장 계획 — 시나리오 실제성 점검, 도커·쿠버네티스, 문제 보강, 확장 대비

작성: 2026-10-22 · 상태: **5절 확장 대비 완료**(2026-10-22, 커밋 `1623324`·`44c2afd`·`68b91ef`). 시나리오 보강(3절)은 사용자 진행 신호 대기

## 1. 지금 13개 문제는 실제로 자주 일어나는가

공개 자료로 확인한 큰 흐름:

- **설정·변경·절차 문제가 대부분이다.** Uptime Institute 2024 요약: 최근 심각한 장애의 4/5는 관리·절차·설정을 개선했으면 막을 수 있었다고 응답. 업계 인용(Gartner 등)도 계획 외 중단의 약 80%를 사람·절차 문제로 본다(2차 인용, 오래된 수치라 참고만).
- **IT 서비스 장애의 가장 큰 단일 원인은 네트워크·연결성**(응답자의 31%가 지목, 2025 보고서 30%).
- **공개 포스트모템 모음**(danluu/post-mortems)의 "Config Errors"에 인증서 만료(crates.io, docs.gluster.org, haskell.org)와 DNS 설정 사고(AWS 서울 리전 VPC DNS, GitHub 네임서버)가 반복해서 나온다.

13개 문제를 이 흐름에 대 보면:

| 분류 | 문제 | 실제성 근거(유형) |
|---|---|---|
| Linux | 로그가 디스크 가득 채움, OOM, 권한 403, 포트 충돌 | 자원 고갈·배포 후 권한·포트 점유는 대표적 운영 사고 |
| Network | DNS(resolv.conf), 방화벽, localhost 바인딩 | 네트워크가 IT 장애 1위, DNS 설정 사고 포스트모템 다수 |
| Web·DB | nginx 설정 오류 후 재시작, 인증서 만료, DB 연결 상한 | 변경 유발 장애, 인증서 만료 포스트모템 다수 |
| AWS | 보안 그룹, IAM 권한, ALB 헬스체크 경로 | 클라우드 설정 오류(권한·네트워크 규칙) |

결론: 13개 모두 **"설정/변경 실수 + 자원 고갈 + 네트워크"** 라는 실제 상위 원인군에 들어간다. 다만 지금은 근거가 문서 밖에만 있으므로, **시나리오마다 근거 출처를 데이터로 붙이고 테스트로 강제**하는 것을 제안한다(3절).

빠져 있는 자주 일어나는 유형(후보): nginx 502(업스트림 다운·포트 오기), inode 고갈(`df -h`는 여유인데 `df -i` 100%), Too many open files(EMFILE), 배포 후 롤백, 시간 동기화(NTP) 오류.

## 2. 도커·쿠버네티스 섹션을 추가할까 → **추가 권장**

인프라·클라우드 개발자 대상이라면 컨테이너 장애는 빠질 수 없다. 자주 거론되는 유형:

- **Kubernetes**: CrashLoopBackOff(설정·명령 오류, `kubectl logs --previous`, `describe`의 Last State), OOMKilled(종료 코드 137, 메모리 limit), ImagePullBackOff(이미지 이름·태그 → 레지스트리 인증 → 네트워크 순서로 확인), readiness 실패로 Service 엔드포인트 없음(503). 공개 실패 사례 모음 k8s.af에는 DNS·conntrack·CPU limit 스로틀링 사례가 많다.
- **Docker**: 포트 이미 할당됨(`docker ps`, `ss -tlnp`), 이미지·빌드 캐시로 디스크 가득(`docker system df` → `prune`), 컨테이너가 바로 종료(`docker logs`).

**공식 문서 라이선스(원본 LICENSE 파일로 확인)**: Kubernetes 문서 **CC BY 4.0**, Docker 문서 **Apache 2.0**. 둘 다 출처 표시로 지식 근거에 넣을 수 있다(기존: curl 라이선스, Linux man-pages 계열, AWS 문서 CC BY-SA 4.0).

**캠퍼스 자리**: 지금 3×3 격자 중 6칸을 쓰고 (24,0)·(0,24)·(24,24) 세 칸이 비어 있다. 레이아웃을 바꾸지 않고 **컨테이너 운영실(Docker)·쿠버네티스 운영실(Kubernetes)** 두 방을 넣을 수 있다. (방 이름은 사용자 결정으로 "○○ 운영실" 형식)

## 3. 문제 보강 계획(제안: 13 → 24개)

| 묶음 | 새 문제(가칭) | 엔진에 필요한 것 |
|---|---|---|
| Linux·Web 보강(3) | nginx 502 업스트림 다운, inode 고갈, Too many open files | `df -i`·파일 수 모델, nginx upstream 응답 계산, ulimit 값 |
| Docker(3) | 포트 이미 할당, 이미지·캐시로 디스크 가득, 환경변수 누락으로 즉시 종료 | 컨테이너·이미지 상태 모델, `docker ps/-a, logs, images, system df/prune, start/stop/rm, inspect` |
| Kubernetes(5) | CrashLoopBackOff, OOMKilled, ImagePullBackOff, readiness 실패 503, 잘못된 Service selector | 파드·디플로이먼트·서비스·이벤트 모델, `kubectl get/describe/logs [--previous]/rollout undo/set image/set resources` |

원칙은 그대로: 출력은 상태에서 계산, 시나리오는 데이터 파일 하나, 티켓엔 증상만, 힌트 3단계, 포스트모템 4항목, 자동 검증(모범 풀이로 복구·명령 커버리지).
