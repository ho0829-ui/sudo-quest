# 23. 정기 검증 체크리스트 (D5)

기능을 추가하거나 고칠 때마다 **같은 순서**로 돌린다. 결과는 HANDOFF의 "검사" 줄에 숫자 그대로 적는다(통과·실패·미실행을 구분).
명령은 저장소 루트 기준이고, 백엔드는 `backend` 폴더에서 Mac 가상환경(`.venv/bin/python`)으로 실행한다. Windows는 `.venv/Scripts/python.exe`.

## 1. 자동 검사 (무료, 항상)

| 순서 | 명령 | 통과 기준 |
|---|---|---|
| 1 | `npm run typecheck` | 오류 0 |
| 2 | `npx vitest run --testTimeout=60000` | 전부 통과(부하가 높으면 기본 5초 제한에 걸리므로 60초로) |
| 3 | `npm run build` | 성공 |
| 4 | `cd backend && .venv/bin/python -X utf8 -m unittest discover -s tests` | OK |
| 5 | `cd backend && .venv/bin/python -X utf8 -m scripts.validate_catalog` | 실패 0 |
| 6 | `git diff --check` | 출력 없음 |

- 새 시나리오: `tests/scenarios.test.ts`(풀이·스키마)는 자동, `tests/scenario-exploration.cases.ts`에 정답 밖 탐색 사례를 직접 추가한다.
- 새 명령: 단위 테스트 + 필요하면 `src/ui/unsupportedCommands.ts`(대안 안내)·`src/ui/glossary.ts`(용어 풀이) 갱신.

## 2. RAG 검색 회귀 (무료에 가까움, 백엔드·색인을 바꿨을 때)

- `cd backend && .venv/bin/python -X utf8 -m scripts.evaluate_v2 retrieval`
- 질문 벡터는 `data/evaluation/`에 캐시되어 두 번째부터 임베딩 호출 0회(질문을 고치면 그 질문만 1회).
- 기준: 22번 문서 3절의 값(항목 범위 Hit@4·MRR, 전체 Hit@4·10, 항목 자동 선택 Hit@3)보다 떨어지면 원인을 찾는다.
- 답변까지(`answers`)는 유료라 모델·프롬프트·검증 규칙을 바꿨을 때만, 호출 수를 보고하고 돌린다.

## 3. 브라우저 점검 (화면을 바꿨을 때)

- 개발 서버는 `.claude/launch.json`의 `dev`(5173)·`api`(8000). 검사는 **`127.0.0.1:5173` 출처**에서 한다(사용자가 쓰는 `localhost:5173` 저장소를 건드리지 않으려고).
- 크기: 1280×720(낮은 노트북), 1440×900, 375·414px(휴대폰).

| 화면 | 볼 것 |
|---|---|
| 홈 | 시작 버튼·튜토리얼 버튼이 첫 화면 안, 카드 색·호버, 가로 넘침 없음 |
| 튜토리얼 | 말풍선 8단계 진행, Esc 건너뛰기, 기록·점수에 안 남음 |
| 실습 | 입력줄이 첫 화면 안, 미지원 명령 안내 펼침, 힌트·용어 풀이, 원인 제출(오답 포함) |
| 리포트 | 등급·점수·포스트모템, 파일 저장 이름 |
| 코치 | API 켠 상태에서 질문 1개(유료 1~2회), 끈 상태에서 "오프라인" 안내 |
| 게시판·글·자료실·기록 | 첫 화면 밀도, 카페 접기, 태그 글씨 |
| 피날레·크레딧 | 저장소에 올클리어 기록을 넣어 열기, 소리 끄기·볼륨 |

- 콘솔 오류 확인(API를 끈 상태의 `/api` 500은 예상된 것).
- **끝나면 테스트 저장소를 비운다**(127.0.0.1 출처의 localStorage·sessionStorage), 화면 크기 원래대로.
