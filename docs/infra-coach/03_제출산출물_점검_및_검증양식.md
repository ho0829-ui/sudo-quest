# 제출 산출물 점검 및 검증 양식

점검일: 2026-10-21 · 현재 단계: 기획·설계, 신규 RAG 코드 미구현

## 1. 제출 산출물 6종 대조 결과

| 번호 | 제출물 | 기존 문서 포함 여부 | 현재 판단·남은 작업 |
|---|---|---|---|
| 1 | 요구사항 정의서 | 기획서 5절, 구현 명세서 10~12절에 필수·심화·비기능 표 있음 | 설계 대응 있음. 항목 수·출처·이용 조건의 실제 충족 증빙은 미확보. 제출 시 독립 문서로 정리 |
| 2 | RAG 파이프라인 설계문서 | 구현 명세서 3~6절에 컬렉션·청킹·프롬프트 3개·Top-k 있음 | v0.2에서 설정 선정 이유·비교 방법 보강. 최종 구현과 프롬프트 전문 반영 필요 |
| 3 | 검증 결과 | 요구사항 대조표와 일부 테스트 예시 있음 | 상호 체크 양식과 전체 결과 기록란이 부족해 이 문서에 보완. 실행 결과는 아직 없음 |
| 4 | 구현 소스코드 | 모듈·API 설계 있음. 기존 게임 ZIP 별도 존재 | RAG 수집·색인·그래프·심화 코드는 미구현. 설계문서로 대체 불가 |
| 5 | 셀프 체크리스트 | 실시 계획만 있음 | 공식 양식은 3일차 오후 수령 예정. 아래 사전 점검표는 공식 양식 대체물이 아님 |
| 6 | README.md | 작성할 내용이 기획서에 기재됨 | 신규 RAG 프로젝트용 실행 README는 아직 없음. 실제 실행을 확인한 후 작성 |

결론: 제출물의 설계 범위는 잡혀 있지만 6종 모두 제출 준비가 끝난 상태는 아니다. 이번 보완은 체크 양식과 설계 이유의 누락을 채운 것이며, 실제 테스트·동료 점검·공식 셀프 점검을 대신하지 않는다.

## 2. 제출 직전 점검표

### 1) 요구사항 정의서

- [ ] F2001~F2012 필수 표와 상세 완료 기준이 있다.
- [ ] F2013~F2016의 선택/미선택 및 구현 결과를 표시했다.
- [ ] NF2001~NF2007의 충족 방법과 결과를 기록했다.
- [ ] 고유 지식 항목 약 100건 이상을 확보하고 실제 건수·확인일·목록 파일을 기록했다.
- [ ] 각 항목을 설명하는 외부 문서가 연결돼 있다.
- [ ] 출처와 이용 조건 확인 기록이 있다.
- [ ] 근거가 필요한 질문 3개 이상과 근거 없는 답변의 문제를 설명했다.
- [ ] 위험 도메인 해당 여부 및 필요한 안내를 명시했다.

### 2) RAG 파이프라인 설계문서

- [ ] 두 컬렉션과 메타데이터·청크 ID 규칙을 설명했다.
- [ ] 검색어 추출→후보 선별→본문 수집→청킹→색인 흐름이 있다.
- [ ] 프롬프트 3개의 역할·입력·출력·실제 적용 문구가 있다.
- [ ] 청크 크기·중복 길이·Top-k의 값과 선정 이유가 있다.
- [ ] 설정 변경 전후 결과와 최종값을 기록했다.
- [ ] 선택 항목 메타데이터 포함·외부 검색·병합·중복 제거를 설명했다.
- [ ] retrieve/generate 두 노드 구조와 실제 인용 표시 방식을 설명했다.
- [ ] 특화 기능의 근거 사용과 관찰 기록의 구분을 설명했다.
- [ ] 구현 중 겪은 문제·해결 과정·남은 한계를 기록했다.

### 3) 검증 결과

- [ ] 요구사항별 테스트·증빙 연결이 있다.
- [ ] 테스트 결과표에 입력·기대·실제·판정·증빙이 있다.
- [ ] 필수·비기능 및 선택 심화의 실행 결과가 있다.
- [ ] 화면 캡처와 그래프/서버 실행 기록을 첨부했다.
- [ ] 동료가 실제로 수행한 상호 체크리스트가 있다.
- [ ] 실패·미확인 항목을 통과로 바꾸지 않았다.
- [ ] F2015: 동일 질문 5개 이상의 전후 답변과 정확성·근거·보류 비교가 있다.

### 4) 구현 소스코드

- [ ] 데이터 수집·정제·색인 스크립트가 있다.
- [ ] RAG 그래프·프롬프트·검색·서비스·UI가 구현돼 있다.
- [ ] 선택한 심화 기능 코드가 포함돼 있다.
- [ ] 기존 코드 재사용 범위와 신규 변경을 설명했다.
- [ ] 의존성·설정 예시·실행 절차가 있고 API 키는 제외했다.

### 5) 셀프 체크리스트

- [ ] 3일차 오후 제공된 공식 양식을 확보했다.
- [ ] 실제 최종 버전을 기준으로 직접 점검했다.
- [ ] 공식 양식에 결과를 작성하고 증빙을 연결했다.
- [ ] 양식 원본/작성본을 제출물에 포함했다.

### 6) README.md

- [ ] 프로젝트 목표·대상·주요 기능·필수/심화 구분이 있다.
- [ ] 필요한 런타임·설치·환경변수 이름을 설명했다.
- [ ] 데이터 준비·수집·색인·서버·화면 실행 명령을 검증했다.
- [ ] 실제 지원 모델·임베딩·설정 방법을 명시했다.
- [ ] 출처·이용 조건·버전·갱신 방식이 있다.
- [ ] 테스트 실행·시연 절차·알려진 한계를 기록했다.
- [ ] 새 작업 폴더에서 README만 보고 로컬 실행을 재현했다.
