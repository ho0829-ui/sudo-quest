# GPT ↔ Claude 작업 전환 가이드

## 원칙

모델 간 대화 기억이 자동 이전되는 것으로 가정하지 않는다. 같은 코드 버전과 PROJECT/TASKS/HANDOFF를 기준으로 이어간다. 사용량 제한 때문에 대기하는 상황과 대화 맥락 길이 한도는 다를 수 있으며, 전환만으로 특정 서비스의 한도가 복구된다고 가정하지 않는다.

## 한 번 준비할 것

1. 실제 게임 저장소에 `docs/infra-coach/` 폴더를 만들고 이 폴더의 설계·점검·인수인계 Markdown을 보관한다.
2. 과제 PDF와 현재 소스를 접근 가능한 상태로 둔다. 원본 과제는 외부 공개 저장소에 무조건 올리지 않는다.
3. 실행 설정은 `.env.example`에 변수 이름만 기록하고 실제 키는 로컬 환경에 둔다.
4. 인수인계 파일의 위치를 작업 시작 메시지에 명시한다. 도구별 자동 파일 인식에 의존하지 않는다.

현재 이 문서들은 설계 폴더에만 있다. 실제 게임 저장소로 옮기거나 연결하는 작업은 아직 하지 않았다.

## 작업을 넘길 때마다

- 모든 편집을 저장하고 코드와 문서가 같은 시점인지 확인한다.
- TASKS의 완료/미완료와 HANDOFF의 변경 파일·시험 결과·오류·다음 작업을 갱신한다.
- Git을 사용하면 브랜치·커밋·미커밋 변경을 기록한다. 미커밋 파일도 전달돼야 한다.
- 데이터와 색인의 재생성 절차·원본 목록·임베딩 모델을 기록한다. 다른 PC라면 필요한 데이터 파일도 전달한다.
- 테스트는 실제로 실행한 것만 기록한다. 큰 기능 완료 때마다 갱신해 한도 소진 직전 정리를 놓치지 않는다.

## Claude에 전달할 방법

### 같은 컴퓨터에서 코드 폴더에 접근할 수 있는 경우

같은 실제 저장소를 열고 아래 프롬프트와 문서 경로를 전달한다. 앞 도구의 파일 편집이 끝난 상태에서 이어간다. 동시에 같은 파일을 편집하게 하지 않는다.

### 파일 업로드 방식의 대화를 쓰는 경우

현재 소스와 설계·인수인계 문서를 함께 전달한다. 로컬 경로만 적어서는 내용을 읽을 수 없다. `.env`, API 키, `node_modules`, `.venv`, 불필요한 빌드 결과는 전달하지 않는다. 업로드 가능한 크기에 따라 소스/문서를 나눠 전달한다. 캐시를 제외하면 수집·색인을 재현할 자료와 방법은 반드시 남긴다.

## 복사해서 사용할 시작 프롬프트

```text
InfraCoach 프로젝트 작업을 이어가려고 합니다.

첨부하거나 접근을 제공한 PROJECT.md, HANDOFF.md, TASKS.md를 먼저 읽고,
01_프로젝트_기획서.md, 02_구현_명세서_요구사항_대조표.md,
03_제출산출물_점검_및_검증양식.md와 원본 과제 PDF를 확인해 주세요.

이 프로젝트는 기존 장애 대응 게임에 RAG 코칭을 연결하는 1인 3일 프로젝트입니다.
React/TypeScript 게임을 활용하고 Python RAG 서버를 추가하며 로컬 시연이 우선입니다.
지식 항목 100건과 실행 가능한 실습 수는 다릅니다.
게임 판정은 엔진이 맡고, 코치는 공개된 관찰 기록과 공식 문서로만 설명합니다.
필수 F2001~F2012와 NF2001~NF2007, 선택 심화 F2013/F2015를 유지해 주세요.

먼저 실제 파일과 Git 상태를 확인해 인수인계 기록과 다른 점을 짧게 알려주세요.
기존 구현을 확인하지 않고 처음부터 재작성하지 마세요.
설계 완료·구현 완료·실행 검증 완료를 구분하고 테스트 결과를 추정하지 마세요.
소스나 원본 문서가 전달되지 않았다면 필요한 자료를 명확하게 요청해 주세요.

이어서 TASKS의 가장 앞선 미완료 작업을 진행해 주세요.
기능 하나를 끝낼 때마다 TASKS와 HANDOFF에 변경·실제 검증·다음 작업을 갱신해 주세요.
API 키는 파일이나 대화에 기록하지 마세요.
```

이 프롬프트를 보내는 시점에는 구현을 시작·계속하도록 요청하는 의미가 포함된다. 설계 검토만 원하면 마지막 ‘미완료 작업을 진행’ 문장을 원하는 검토 요청으로 바꾼다.

## GPT로 돌아올 때

같은 절차로 최신 코드와 갱신된 문서를 전달한다. 시작 프롬프트는 그대로 재사용해도 된다. 이전 GPT 대화 내용보다 최신 HANDOFF와 실제 코드 변경을 먼저 확인하도록 한다.
