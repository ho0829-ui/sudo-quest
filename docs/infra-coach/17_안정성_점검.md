# 17. 웹페이지 안정성 점검 (2026-10-22, Mac, Claude)

사용자 요청: "시나리오는 늘리는 건 일단 잠정 중단하고 웹페이지 안정성 검사…" → Phase 1(안정성 점검) 승인.

목표: 화면 하나의 오류·배포 직후 조각 파일 누락·손상된 저장소·백엔드 꺼짐·이상한 주소·긴 사용에서도 게임이 흰 화면으로 멈추지 않는지 확인하고, 찾은 문제를 고친다.

## 1. 찾은 문제와 조치

| # | 문제 | 재현 | 영향 | 조치 | 검증 |
|---|---|---|---|---|---|
| 1 | 화면 오류 방어(Error Boundary) 없음 | 렌더 중 예외 1개, 또는 지연 로딩 조각(PlayScreen 등) 받기 실패 | 앱 전체가 흰 화면 | `ui/components/ErrorBoundary.tsx`: 앱 전체(main.tsx)·화면 구역(주소가 바뀌면 다시 그림)·코치/힌트 패널(터미널은 계속 사용) 3단. 조각 파일 오류는 "새 버전 배포 → 새로고침" 안내, 그 밖은 "다시 시도·홈으로". 자세한 오류는 콘솔에만 | `stability.test.tsx` 오류 안내 2개 |
| 2 | `crypto.randomUUID`는 HTTPS·localhost에서만 있음 | `http://192.168.x.x:5173`처럼 IP로 접속(스터디원 공유) 후 실습 입장 | 코치 패널 생성 시 TypeError → 실습 화면 멈춤 | `ui/randomId.ts`: 없으면 `getRandomValues`로 UUID v4 생성 | randomUUID 없는 환경 테스트 |
| 3 | 지식·코치·조건 탐색 응답의 모양을 확인하지 않음 | 백엔드 버전 불일치·프록시 오류 페이지(200 HTML) | `response.json()` 예외 또는 렌더 중 undefined 접근 | `api/validate.ts`(isAnswer·isCoachAnswer·isExploreResult·isItems·isJobStart), `api/knowledge.ts`의 모든 요청이 검사 후 반환, 실패 시 "서버 응답 형식이 올바르지 않습니다" | 응답 모양 테스트 |
| 4 | 탭에 저장한 대화 턴은 바깥 모양만 확인 | 손상·옛 형식 저장본(`[42, {question:1}]`) | 코치·지식 화면 렌더 오류 | `useStoredState.sanitizeTurns`: 질문 없는 턴은 버리고, 결과 모양이 다르면 결과만 버림 | 대화 기록 테스트 |
| 5 | 명령 구현의 예외가 실습 화면까지 번질 수 있음(안전망 없음) | 엔진 버그(이번 점검에서는 발견되지 않음) | setState 안 예외 → 화면 오류 | `engine/run.ts`: 명령 예외를 잡아 그 줄만 `[시뮬레이터 오류]`로 끝내고 상태는 실행 전으로 | 예외 주입 테스트 |
| 6 | 없는 주소가 주소창에 그대로 남음 | `#/mission/99/play`, `#/community/abc` | 홈이 보이는데 주소는 그대로라 북마크·공유가 어긋남 | App: 첫 로드·이동 때 보이는 화면의 주소로 `replaceState` | 브라우저: 5개 주소 정규화 확인 |

## 2. 문제없음을 확인한 것

- **엔진 퍼징**(`tests/fuzz.test.ts`): 24개 실습 × 사용 가능한 모든 명령 × 이상한 인자 56종(빈 따옴표, `/proc`, 2000→500자, 음수·거대 수, 한글, `-f '{{.Nope}}'` 등) × (일반·sudo). **예외 0건**, `undefined`·`NaN`·`[object Object]` 노출 0건(입력을 되풀이한 경우 제외). 약 10초.
- **모든 실습 화면 렌더링**(`stability.test.tsx`): 24개 실습의 브리핑·실습(풀기 전·후)·리포트, 빈 기록·전부 클리어한 실습 목록.
- **이상한 주소 19종**: 어떤 주소든 화면 하나로 정해지고 다시 주소로 만들어도 같은 화면.
- **저장소**: 읽기 막힘(시크릿 모드), 쓰기 용량 초과, 손상된 JSON에서 학습 기록·진행 중 실습 모두 예외 없음.
- **긴 사용**: docker-disk-full에서 명령 300개 실행 + 저장 + 복원 0.8초(명령당 약 1.4ms), 저장본 20KB 미만, 복원 상태 동일.
- **브라우저(개발 서버 5173, 별도 탭)**:
  - 주소 35개(홈·지식·기록·게시판·글쓰기·실습 24개 브리핑·잘못된 주소)를 돌며 콘솔 오류 0, 오류 안내 패널 0.
  - 가로 넘침: 375px(8개 화면 + 실습 화면) 0, 768px 0(뉴스 티커는 숨김 영역 안에서 흐르는 의도된 동작), 1280px 0.
  - 백엔드를 끈 상태: 상단 "코치 오프라인 · 가상 실습은 바로 이용", 지식 목록 "다시 불러오기", 게시판 개수 "—", 실습 터미널 정상, 새로고침 후 진행 중 실습 복원 정상. 검사 뒤 API를 다시 띄움.
  - 접근성 이름: 홈의 포커스 가능한 요소 101개 모두 이름 있음, alt 없는 이미지 0.

## 3. 하지 않은 것·한계

- 실제 휴대폰 기기, Safari·Firefox(검사는 앱 내장 Chromium), 화면 읽기 프로그램 실제 사용, 느린 네트워크 실측은 하지 않음.
- 지연 로딩 조각 받기 실패는 브라우저에서 재현하지 않고 단위 테스트로만 확인(오류 문장 판별·안내 렌더링).
- 게시판 응답 검증은 기존(`api/community.ts`)에 이미 있어 그대로 둠.
