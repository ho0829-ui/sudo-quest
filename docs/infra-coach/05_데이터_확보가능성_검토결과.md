# InfraCoach 데이터 확보 가능성 검토

검토일: 2026-10-21 · 판정: **수량·기술적 수집 가능성 확인, 최종 데이터 품질·이용 조건 정리 전**

## 1. 결론

도메인을 유지하고 환경 구축 및 데이터 정제 단계로 진행할 근거가 있다. 공개 문서 3개에서 독립적인 오류 코드·문제 해결 절 후보 237건을 실제 추출했고, 우선 검토할 100건을 선택했다. 그러나 ‘최종 검수된 장애 데이터 100건 확보 완료’로 과제 조건을 통과 처리하지 않는다.

현재 주제는 ‘인프라 장애·오류 진단 지식과 실습 코칭’이다. 수집된 항목은 실제 사고 사례 100개나 실행 가능한 실습 100개가 아니다. 오류·문제 해결 주제를 독립 항목으로 정의한다는 기획을 유지해야 한다.

## 2. 실제 수집 결과

| 출처 | 추출 후보 | 1차 우선 후보 | 최종 검토 대상으로 선택 | 접근·설명 확인 |
|---|---:|---:|---:|---|
| curl 명령어 매뉴얼의 Exit codes | 86 | 57 | 40 | HTML 본문 다운로드·코드별 설명 추출 성공 |
| Linux man-pages errno(3) | 123 | 64 | 40 | HTML 본문 다운로드·오류 이름별 설명 추출 성공 |
| AWS ALB 트러블슈팅 | 28 | 28 | 20 | HTML 본문 다운로드·제목/절/설명 추출 성공 |
| 합계 | **237** | **149** | **100** | 세 출처 모두 본문 확보 |

‘1차 우선’은 자동 규칙 및 작성자 선정 기준이며 서비스 품질 검수 점수가 아니다. 최종 검토 대상으로 40/40/20건을 명시적으로 골랐다. 분야가 Linux·네트워크·AWS에 편중돼 있으며 NGINX·DB 전용 자료는 이번 조사에 포함하지 않았다.

- https://docs.aws.amazon.com/elasticloadbalancing/latest/application/load-balancer-troubleshooting.html

## 3. 집계 기준

- curl: 문서에 실제 있는 종료 코드 절만 집계하고 정상 종료 0은 제외했다. libcurl 오류 목록과 별도 집계해 중복으로 더하지 않았다.
- Linux: 오류 이름 절을 추출했다. EDEADLOCK·ENOTSUP·EWOULDBLOCK 별칭 항목은 제외하고 설명이 10자 이하인 ENOANO도 제외했다. 일부 별칭 관계는 플랫폼 조건이 있으므로 정제 시 확인한다.
- ALB: 문제별 h2/h3 절을 집계했다. 오류 목차 상위 제목과 리소스 맵/optimizer 묶음은 제외했다. 상위 진단 절과 구체 HTTP 오류 사이의 의미 중첩은 추가 검수 대상이다.
- 동일 ID 중복은 0건이다. 의미 중복까지 완전히 제거됐다는 뜻은 아니다.
- curl exit 7, Linux ECONNREFUSED, ALB 502처럼 관련 증상이 있어도 계층·제품·코드 의미는 다르다. product/code_scope를 명시하고 문맥 없이 서로 같은 오류로 취급하지 않는다.
- 문서 청크 개수를 항목 개수로 계산하지 않았다. 항목마다 원문 제목·코드·출처 URL·절·설명 길이가 있다.

## 4. 품질상 발견 사항

237건 중 원문 설명이 80자 미만인 항목은 187건(curl 71, Linux 114, ALB 2)이다. 길이 자체가 품질을 뜻하지는 않지만, 많은 항목이 오류 뜻만 설명하고 진단·조치 조건은 별도 문서에서 설명한다.

따라서 오류 목록은 메타데이터를 만드는 재료로 적합하고, 이를 그대로 코칭 문서 전체로 삼기에는 부족하다. ‘Connection refused’라는 정의만으로 원인과 해결 명령을 확정하면 안 된다.

보강 가능성도 실제 확인했다.

| 보강 문서 | 결과 | 사용 시 주의 |
|---|---|---|
| libcurl error codes | HTTP 200·본문 확보 | curl CLI와 API 문맥 구분. 새로운 후보 건수에 더하지 않음 |
| Linux connect(2) | HTTP 200·본문 확보 | 연결 호출의 조건별 errno 설명 |
| Linux open(2) | HTTP 200·본문 확보 | 파일 열기·권한·자원 제한 맥락 |
| Linux write(2) | HTTP 200·본문 확보 | 쓰기 실패·공간·파이프 등의 맥락 |
| AWS 타깃 헬스체크 | HTTP 200·본문 확보 | unhealthy/unused/fail-open 동작 검증 |

선택된 Linux 40건 중 31건의 오류 이름이 connect/open/write 보강 문서에 등장한다. 이는 원문 연결 가능성 검사이며 각 오류의 해결 방법까지 검수됐다는 뜻은 아니다. 나머지 9건에는 추가 문서를 찾아야 한다.

보강 출처:

- https://curl.se/libcurl/c/libcurl-errors.html
- https://man7.org/linux/man-pages/man2/connect.2.html
- https://man7.org/linux/man-pages/man2/open.2.html
- https://man7.org/linux/man-pages/man2/write.2.html
- https://docs.aws.amazon.com/elasticloadbalancing/latest/application/target-group-health-checks.html

## 5. 이용 조건 확인 범위

| 출처 | 확인 내용 | 남은 조치 |
|---|---|---|
| curl | 공식 저작권 페이지에서 curl 라이선스와 배포 아카이브 콘텐츠의 사용·수정·재배포 안내 확인 | 사용하는 문서 버전을 고정하고 원문 고지·허가문 보존, 수집 경로 정책 기록 |
| AWS docs | AWS Site Terms에 docs.aws.amazon.com 문서는 CC-BY-SA-4.0, 내부 코드 예시는 MIT-0라고 명시됨 | 저작자·원문·라이선스·변경 표시 및 배포 조건을 산출물에 반영. 사이트 전체 무제한 크롤링 허가로 해석하지 않음 |
| Linux man-pages | 과거 errno.3 원본에서 GPLv2+ 문서 고지를 확인 | 이번 HTML과 원본 버전의 일치가 확인되지 않음. 실제 사용할 릴리스 원본 및 개별 보강 문서 라이선스를 고정·기록해야 함 |

확인 링크:

- curl: https://curl.se/docs/copyright.html
- AWS: https://aws.amazon.com/terms/ 의 LICENSE AND SITE ACCESS
- Linux 과거 원본(2021-03-22 표기, 현재 HTML과 동일 버전으로 간주하지 않음): https://raw.githubusercontent.com/mkerrisk/man-pages/master/man3/errno.3

공식 라이선스 안내를 찾았다는 사실과 최종 제출 패키지의 조건 준수 완료를 구분한다. 현재 결과물에는 후보 식별정보·출처·메타데이터를 담고, 수집한 전체 본문은 작업용 캐시에 두었다.

## 6. 기존 게임 연결 예시

| 기존 실습 | 연결 가능한 후보 |
|---|---|
| linux-disk-full | ENOSPC, EDQUOT, curl 쓰기 오류 |
| linux-permission | EACCES, EPERM |
| linux-port-conflict | EADDRINUSE |
| linux-oom | ENOMEM |
| network-dns | curl exit 6 |
| network-firewall / network-bind-localhost | curl exit 7/28, ECONNREFUSED, ETIMEDOUT |
| web-ssl-expired | curl exit 60 및 TLS 관련 문서. 코드 60만으로 만료라고 확정하지 않음 |
| aws-alb-healthcheck | ALB 타깃 상태·HTTP 오류·공식 헬스체크 문서 |

연결 가능한 후보 예시이며 실습 원인 자동 판정 규칙이 아니다. IAM/S3·DB 전용 자료와 NGINX 설정 문서는 별도로 보강해야 한다.

## 7. 다음 작업과 최종 데이터 통과 기준

1. 100건 목록의 제품·오류 범위·한국어 제목·증상·관련 문서·출처를 정규화한다.
2. 짧은 설명 항목에 진단 조건을 설명하는 문서를 연결한다. 없는 해결 절차를 LLM으로 채우지 않는다.
3. 유사 항목을 검토하고 같은 의미의 중복을 정리한다. 제거 후 100건 미만이면 남은 후보나 새 공식 출처에서 보충한다.
4. 실제 사용하는 문서 릴리스·라이선스·수집 규칙을 고정한다.
5. 게임과 연결되는 10건으로 검색·인용 답변을 시험한다. 효과가 확인되면 전체 색인한다.
6. 고유 100건 이상·필수 메타 필드·본문 연결·출처/조건 기록·재색인 중복 없음까지 확인한 후 과제 데이터 조건을 통과로 표시한다.

현재 API 키나 유료 검색 API 없이 자료를 확보했다. 임베딩·생성 API 호출과 검색 품질 시험은 아직 수행하지 않았다.

## 8. 생성 파일

- `data_feasibility/candidate_catalog.json`: 후보 237건의 메타데이터.
- `data_feasibility/candidate_catalog.md`: 사람이 읽는 전체 목록.
- `data_feasibility/shortlist_100.json`: 우선 검토 100건과 보강 링크.
- `data_feasibility/shortlist_100.md`: 우선 검토 목록.
- `data_feasibility/audit_counts.json`: 집계·제외 규칙 결과.
- `data_feasibility/supplementary_fetch_manifest.json`: 추가 수집 HTTP 상태·본문 해시.

개별 URL의 서버 응답을 237번 요청한 것은 아니다. 세 원문을 내려받고 각 항목의 절을 추출했다. curl/AWS의 항목 URL은 해당 원문의 실제 anchor를 사용했고, Linux는 동일 errno 문서에 오류 이름으로 위치를 지정했다.
