# 정답 경로 밖의 시나리오 탐색 점검

2026-10-22 · Mac · feature/sudo-quest

사용자 요청: 정답 명령어만 검사하지 말고, 코드를 직접 입력하며 비슷한 명령·조회·다른 접근을 시험할 것.

## 실행 범위

모든 **14개 시나리오**에 독립적인 탐색 사례를 작성했다. 실제 시스템 CLI가 아닌 `runCommand`를 통해 같은 가상 엔진에 입력한다.

- 조회: 공통 7개와 시나리오별 4개를 정방향·역방향으로 반복. 원본/반환 상태, 미복구 유지, NaN/undefined 출력 여부 검사.
- 오조치: 재시작만 하기, 다른 포트 열기, 읽기 전용 S3 정책 붙이기, 잘못된 이미지로 바꾸기 등. 복구 판정이 false인지 검사.
- 대체 풀이: 로그 삭제 대신 내용 비우기, chmod 기호 표기, kill -9/-15, 서비스 별칭, 긴 옵션·옵션 순서 변경, SQL --execute= 구문, kubectl 리소스 별칭. 복구 후 다시 조회해 상태 유지 검사.
- 입력 회귀: 시험 실행, 잘못된 옵션·신호·포트·CIDR·ARN·숫자, 불완전한 따옴표와 미지원 셸 연산자.

파일: `tests/scenario-exploration.cases.ts`, `tests/scenario-exploration.test.ts`, `tests/exploration-regressions.test.ts`. 이 세 파일의 검사는 74개. 새 시나리오가 등록됐는데 사례가 없으면 실패한다.

## 재현한 문제와 수정

첫 탐색 검사: **60개 중 18개 실패**, 42개 통과. 실패 사례를 고치고 관련 변형을 보강했다.

| 입력/조건 | 수정 전 | 수정 후 |
|---|---|---|
| `sudo kill -0 5218` | 프로세스 종료 | 존재·권한만 확인, 상태 유지 |
| `kill -NOTASIGNAL` | 신호를 무시하고 종료 | 오류, 상태 유지 |
| `sudo certbot renew --dry-run` | 인증서 갱신 | 시험 성공 출력만, 인증서 유지 |
| AWS ingress `--dry-run` | 규칙 추가 | DryRunOperation·255, 규칙 유지 |
| UFW `allow 80/udp` | HTTP 복구로 판정 | TCP와 UDP를 분리, 미복구 |
| AWS UDP 22 또는 다른 출발지 CIDR | SSH 복구로 판정 | TCP와 운영 호스트 출발지 범위 확인 |
| UFW `80/typo`, `99999/tcp` | 정상 규칙으로 등록 | 오류, 상태 유지 |
| rm/systemctl/chmod/chown/sed/ufw의 미지원 옵션 | 무시한 채 변경 | 명시적 오류, 상태 유지 |
| AWS 잘못된 CIDR·포트·옵션 | 무시/저장 | 입력 검증 실패 |
| IAM `garbage/AmazonS3FullAccess`·다른 계정 ARN | 마지막 이름만 보고 권한 부여 | ARN 형식과 가상 정책 목록 확인 |
| `SET GLOBAL max_connections = Infinity` | 무한대 저장, 복구 | 정수·범위 검사 오류 |
| `mysql --execute="SET GLOBAL max_connections = 250;"` | 두 번째 '=' 뒤를 잃음 | 첫 '=' 뒤의 전체 값 보존 |
| `journalctl -n 0`·잘못된 숫자 | 전체 로그 출력 | 0은 빈 출력, 잘못된 값은 오류 |
| `kill 5218; ps aux`·닫히지 않은 따옴표 | 앞 명령만 실행될 수 있음 | 실행 전에 한 줄 전체 문법 검사 |

추가로 다운로드 Markdown 리포트에 빠져 있던 시나리오 참고 자료를 포함했다. 모든 시나리오에 대해 제목/주소 보존을 검사한다.

## 브라우저에서 직접 입력한 검증

`http://127.0.0.1:5173/`, 백엔드를 끈 상태에서 실행했다.

1. Kubernetes 방 입장 → 새 실습 → `get pods -o wide`, `describe pods`, 배포 기록 읽기 → 엔드포인트 없음 → 이미지 변경 → rollout 성공 → 엔드포인트 2개. 원인 모달의 4개 보기 표시도 확인.
2. 375×812 화면에서 명령 입력·복구 출력, 문서 clientWidth/scrollWidth가 둘 다 360px(스크롤바 제외)로 가로 넘침 없음. 화면 크기 복원.
3. 메모리 실습: `ps aux | grep 5218` → `sudo kill -0 5218` → 같은 ps 결과 유지. 잘못된 시그널 오류, `free -m` 조회, `journalctl -n 0` 빈 출력 확인.
4. 방화벽 실습: UDP 80 허용 뒤 미복구 유지, 잘못된 프로토콜·미지원 dry-run 거절. TCP 80 허용 뒤에만 HUD에 복구 표시.

증빙: `evidence/kubernetes/recovery-desktop.png`, `recovery-mobile.png`, `evidence/exploration/kill-zero.png`, `udp-not-recovered.png`.

기존 학습 기록(해결 1건·1000점)을 보존하기 위해 정답을 제출하지 않았다. 테스트 탭은 닫아 탭별 진행 세션을 정리했다. 클리어·세션 재생·리포트 생성은 자동 테스트로 통과했지만 **리포트 UI 완주는 이번 브라우저 검사에 포함되지 않는다**.

별도 `localhost:5173` 테스트 주소는 브라우저 자동 승인 검토에서 접근 거절. 우회하지 않고 기존 승인된 127.0.0.1에서 학습 기록을 변경하지 않는 범위만 검사했다.

## 지원 범위와 다음 점검

- 실제 Linux/Kubernetes/AWS 전체 CLI 호환성 검사가 아니다. 구현한 명령의 학습용 상태 모델을 검증했다. 미지원 옵션·기능은 help 범위를 확인할 것.
- sed는 문자열 치환 모델이며 일반 정규식·여러 스크립트는 미지원. 셸 확장·이스케이프·복합 리다이렉션, 조회 명령 전체의 옵션 유효성은 후속 점검 대상이다.
- Kubernetes는 default 네임스페이스·Recreate·즉시 상태 계산만 구현. 다음 실습에 필요한 logs/previous·resources·undo, RollingUpdate는 별도 구현 필요.
- UFW의 source별 규칙/범위, AWS 사용자 관리 정책·IPv6·복수 리소스, MySQL 전체 변수/SQL은 미지원. AWS 관리형 정책은 프리셋의 `availableManagedPolicies`로 가상 존재 여부를 판단한다.
- 실제 RAG/유료 제공자 호출·재색인·npm audit은 이번 단계에서 실행하지 않았다. 백엔드 코드는 변경하지 않았다.
- 사용자 승인한 게시판 FastAPI+SQLite 구현이 다음 Phase. 번들 분할은 별도 작업.
