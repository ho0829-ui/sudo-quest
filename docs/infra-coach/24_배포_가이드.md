# 24. 배포 가이드 — GitHub Pages + 내 Mac(Tailscale Funnel) (2026-10-23)

처음 배포하는 사람이 혼자 다시 할 수 있게 적은 안내서입니다. 무엇이 어디서 돌고, 켜고 끄는 법, 문제가 생겼을 때 되돌리는 법을 담았습니다.

## 1. 구성

```
https://ho0829-ui.github.io/truble-shooting-game/   게임 화면 — GitHub Pages(무료, 항상 켜짐)
        │  /api 요청 (주소는 빌드할 때 저장소 변수 API_BASE_URL에서 넣음)
        ▼
https://<Mac 이름>.<tailnet>.ts.net                 Tailscale Funnel — 이 Mac의 8000 포트 하나만 밖으로 연결
        ▼
이 Mac 127.0.0.1:8000                               FastAPI (scripts/serve-public.sh) — 코치·지식 탐색·카페
        └─ backend/data/  게시판 SQLite · Chroma 색인 · 답변 캐시 (Git 제외)
```

- **Mac이 켜져 있고 서버를 띄웠을 때**만 코치·지식 탐색·카페가 동작합니다. 꺼져 있으면 게임은 그대로 되고, 상단 배지가 "서버 쉬는 중"으로 바뀝니다.
- **키는 `backend/.env`에만** 있습니다. 공개 설정(허용 출처 `https://ho0829-ui.github.io`, 생성 모델 `gpt-6.1-sol`)은 실행 스크립트가 환경변수로 넘깁니다(`.env`는 고치지 않음).
- 키가 만료되면 새 질문의 코치·지식 답변은 정해진 오류 문장으로 끝나고, **저장된 답변과 카페는 계속** 동작합니다. 새 키를 받으면 `backend/.env`의 `GMS_KEY`만 바꾸고 서버를 다시 켭니다.

## 2. 매번 하는 일

| 하고 싶은 것 | 명령·위치 |
|---|---|
| 서버 켜기 | `scripts/serve-public.sh` (끄기: 그 터미널에서 Ctrl+C) |
| 공개 주소 열기 | `tailscale funnel --bg 8000` (한 번 켜 두면 Mac을 다시 켜도 유지) |
| 공개 주소 닫기(바로 외부 접속 차단) | `tailscale funnel --bg 8000 off` 또는 `tailscale funnel reset` |
| 지금 상태 보기 | `tailscale funnel status`, `curl -s https://<주소>/api/health` |
| 게임 다시 배포 | `master`에 push(또는 PR 합치기) → Actions 탭에서 초록 체크 확인 → 2~3분 뒤 반영 |
| 백엔드 주소가 바뀌었을 때 | `gh variable set API_BASE_URL --body https://<새 주소>` 뒤 Actions에서 다시 실행 |

Mac이 잠들면 접속이 끊깁니다. 시스템 설정 → 배터리(전원 어댑터) → "디스플레이가 꺼져 있을 때 자동으로 잠자기 방지"를 켜 둡니다.

## 3. 처음 한 번 한 일 (기록)

1. 프론트가 백엔드 주소를 `VITE_API_BASE`로 받게 함(`src/api/base.ts`), 서버가 꺼졌을 때 공개용 안내 문구.
2. `scripts/serve-public.sh`(127.0.0.1:8000만 듣고, Pages 출처만 CORS 허용).
3. Tailscale 앱 설치(`brew install --cask tailscale-app`, Mac 비밀번호는 사용자가 입력) → 로그인 → `tailscale funnel --bg 8000`(첫 실행 때 브라우저에서 Funnel 허용).
4. 저장소 변수 `API_BASE_URL` 설정(`gh variable set`).
5. 배포 워크플로(`.github/workflows/deploy.yml`)를 `master` 기준으로 바꾸고, 빌드에 `VITE_API_BASE: ${{ vars.API_BASE_URL }}`.
6. `feature/sudo-quest`를 push하고 `master`로 PR → 테스트 통과 확인.
7. 저장소 Settings → Pages → Build and deployment → Source를 **GitHub Actions**로.
8. PR 합치기 → Actions가 테스트 → 빌드 → 배포.

## 4. 문제가 생기면

| 증상 | 확인할 곳 |
|---|---|
| 게임 주소가 404 | Settings → Pages가 켜져 있는지, Actions 탭의 마지막 실행이 초록인지 |
| 배지가 "서버 쉬는 중" | Mac에서 서버가 떠 있는지(`curl -s 127.0.0.1:8000/api/health`), `tailscale funnel status` |
| 콘솔에 CORS 오류 | 서버를 `serve-public.sh`로 켰는지(다른 방법으로 켜면 Pages 출처가 허용되지 않음) |
| 카페 글쓰기가 "잠시 후" | 1분에 10번 쓰기 제한. 터널을 거치면 모든 방문자가 한 주소로 보여 **전체 합산**이다 |

## 5. 되돌리기

- **외부 접속만 막기**: `tailscale funnel reset` — 게임은 그대로, 코치·카페만 "쉬는 중".
- **게임 사이트 내리기**: Settings → Pages → Source를 끄거나(Unpublish), 합친 커밋을 되돌려 다시 배포.
- **데이터**: 게시판·색인은 이 Mac의 `backend/data/`에 그대로 있다. 옮기거나 지우기 전에 이 폴더를 복사해 둔다.
