## 1-2. 가상 명령 엔진

**한 줄 요약:** 실제 셸을 실행하지 않는다. 시나리오마다 메모리 안에 "가짜 서버 상태(JS 객체)"를 만들고, 명령은 그 상태를 읽어 출력을 계산하거나 복사본을 고친다.

```
시나리오 파일 (데이터)                         플레이어 입력 한 줄
  host 프리셋 + faults[] + resolution + 정답       │
        │ buildInitialState                        ▼
        ▼                                   session/execute.ts
  SystemState (fs·disks·services·processes·        │ runCommand (engine/run.ts)
  journal·memory·network·certificates·             ├ structuredClone(state)  ← 원본은 그대로
  database/aws/kubernetes/docker, clock)           ├ syntaxError: 따옴표·지원 안 하는 셸 연산자(&&, ; 등) 거부
        ▲                                          ├ splitPipeline: | 로 단계 나누기
        │ 새 상태                                  ├ 단계마다 parse → sudo·리다이렉션(>, >>) 분리
        │                                          ├ 시나리오 허용 목록에 없으면 "X: command not found" (127)
        │                                          ├ * glob 확장(실제 셸처럼 명령에 넘기기 전에)
        │                                          ├ command.run({state, tokens, sudo, user, stdin…})
        │                                          ├ 앞 단계 stdout → 다음 단계 stdin
        │                                          └ 리다이렉션은 sudo가 아닌 셸 사용자 권한으로 파일 쓰기
        └──────────────── 결과 {stdout, stderr, exitCode, state}
                                                   │
                         session: 화면 줄 기록 + 명령 기록 → resolution(state) && 원인 정답 ⇒ 클리어 시각 기록
```

- **상태 모델** (`engine/state/`): 파일 트리(크기·권한·소유자), 디스크, 서비스(systemd 유닛·설정 스냅숏), 프로세스(소켓·열린 파일), 저널 로그, 메모리, 네트워크(방화벽·DNS·요청 체인), 인증서(PEM 체인), 그리고 분야별 AWS·Kubernetes(재조정 모델)·Docker(엔진·레이어·docker-proxy). 시뮬레이션 시각 `clock`과 메트릭 자리는 확장용으로 비워 둠.
- **출력은 상태에서 계산**: 예) `df -h` = 그 마운트 아래 파일 크기 합 + 기본 사용량 → 로그를 지우면 자동으로 줄어든다. `ss -tlnp` = 프로세스가 연 소켓 → `kill`하면 포트가 비워진다.
- **명령** (`engine/commands/`, 1파일 1명령 원칙): 지금 등록된 명령은 39개(`help` 포함) — 파일(ls·cat·cd·pwd·tail·head·grep·sort·wc·rm·sed·echo·tee·mkdir·chmod·chown), 시스템(df·du·free·ps·kill·dmesg·systemctl·journalctl·lsof·ulimit), 네트워크·웹(curl·ss·ufw·ping·dig·nginx·openssl·certbot), DB·클라우드·컨테이너(mysql·aws·kubectl·docker — 하위 명령 목록 `operations`를 따로 가짐). 시나리오는 이 중 쓸 것을 `commands` 허용 목록으로 고르고, 목록에 없는 명령은 `help`에도 안 보인다.
- **판정** (`engine/judge/`): `serviceIsActive`, `diskUsageBelow`, `portIsListening`, `httpResponds`, `targetGroupIsHealthy`… 같은 작은 검사를 `all/any/not`으로 조합해 시나리오의 `resolution`을 만든다. 복구 여부는 언제나 이 함수가 상태를 보고 정한다(코치·화면이 정하지 않음).
- **안전망**: 명령 구현이 예외를 던지면 그 줄만 `[시뮬레이터 오류]`로 끝내고 상태는 실행 전으로(안정성 점검 17번).
- **검증**: 모든 시나리오를 자동으로 "주입 직후 미복구 → 모범 풀이 → 복구, 풀이 명령 종료 코드 0, 스키마"로 검사하고, 정답 밖 탐색(조회 반복·역순·오조치·대체 풀이)과 퍼징(이상한 인자 56종)도 돈다.
- **점수** (`engine/session/score.ts`): 1000점에서 감점 — 시간 1분당 10점(최대 200), 명령 12개 초과분 5점(최대 150), 힌트 60점, 오답 80점. 등급 S≥900·A≥750·B≥600·C≥400.

## 1-3. RAG 파이프라인 (백엔드 FastAPI)

### 데이터 준비(오프라인, `scripts.prepare_corpus` 등)

1. **카탈로그**: 학습 항목 131건(`backend/catalog/items.json`, curl·Linux errno·ALB·AWS·Kubernetes·Docker), 항목마다 공식 문서의 **특정 절** 연결과 출처·라이선스 기록. `validate_catalog`가 원문 발췌 일치·허용 라이선스를 검사.
2. **수집**(`collectors.py`): 허용한 공식 페이지만 요청(robots 준수, User-Agent `InfraCoachLearning/0.1`), HTML에서 해당 절만 추출해 해시와 함께 저장.
3. **청킹**: 1000자·겹침 200자(`09_청크_TopK_비교.md`에서 700/1000/1400·k=2/4/6 비교 후 결정).
4. **임베딩**: GMS `gemini-embedding-2`(이전 text-embedding-3-large 3,072차원에서 교체). 같은 본문은 벡터 캐시로 다시 부르지 않음 → 재색인 시 HTTP 0회.
5. **Chroma 컬렉션 2개**: `knowledge_items`(항목 요약 = 메타데이터) / `reference_chunks`(원문 절 청크, `item_id`·`doc_id`·`source_url`). `manifest.json`에 임베딩·청킹 정체성을 적어 설정이 바뀌면 "재색인 필요"로 막음.

### 요청 처리(실행 중) — 모두 비동기 작업: `POST` → `202 {job_id}` → `GET /api/jobs/{id}` 폴링(진행 단계 표시)

**(A) 지식 탐색 질문 `/api/chat`** (`rag.py`, 항목 하나를 골라 묻기)

```
1. 답변 캐시 확인 (질문·대화·코퍼스 해시·모델·top_k·프롬프트 버전) → 있으면 즉시
2. 검색어 추출: LLM(SEARCH 프롬프트)이 영어 기술 용어·오류 코드 최대 3개 → 형식 틀리면 항목명+질문으로 대체
3. 후보 문서 찾기: 허용 공식 페이지 절 목록(section_catalog)에서 키워드로 후보 → (같은 검색어면 캐시)
4. 문서 선별: LLM(SELECT)이 후보 ID 중에서만 최대 4개 + 선정/제외 이유 (새 URL을 만들 수 없음)
5. 수집·색인: 선택된 절 중 아직 없는 것만 가져와 청크·임베딩
6. [LangGraph retrieve 노드] 질문+검색어 임베딩 → reference_chunks에서 이 항목·선택 문서만 top_k=4, 중복 제거
   근거 목록 = [근거 1: 항목 요약] + [근거 2..: 원문 청크]
7. [LangGraph generate 노드] LLM(ANSWER): 근거만 써서 JSON 답변, 모든 주장에 [근거 N]
   → 인용 번호가 실제 근거와 맞는지 검증, 틀리면 1번 다시, 그래도 틀리면 답을 버리고 오류
   → 근거가 2개 미만이면 "문서에서 확인되지 않습니다"로 보류
8. 결과 + trace(검색어·후보·선택·제외 이유·수집 문서·근거 수) 저장 → 화면에 답·인용·원문 링크
```

**(B) 실습 중 AI 코치 `/api/coach`** (`coach.py`)

```
입력: 플레이어에게 보이는 것만 — 티켓, 연 힌트, 직접 친 명령과 출력(번호 붙은 [실습 기록 N]), 사용 가능한 명령
      (정답 ID·풀이·숨은 상태는 보내지 않음: 프론트 요청 빌더 + 서버가 그런 필드를 422로 거부)
1. 캐시 → 2. 검색어 추출
3. retrieve: 항목을 고르지 않았으면 knowledge_items에서 질문과 가까운 항목 3개를 자동 선택(숨은 시나리오-항목 연결은 쓰지 않음)
   → 그 항목들의 reference_chunks top_k=4
4. generate: [근거 N]·[실습 기록 N] 인용 검증, 가상 터미널이 지원하지 않는 명령(하위 명령까지)을 제안하면 경고 붙임
```
