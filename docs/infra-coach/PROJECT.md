## 반드시 유지할 설계

- 100건은 고유 장애 지식 항목 수다. 실습 100개·청크 100개가 아니다.
- 두 컬렉션: knowledge_items / reference_chunks.
- 세 프롬프트: 검색어 추출 / 문서 후보 선별 / 근거 기반 답변.
- LangGraph 답변 부분은 retrieve→generate 두 노드.
- 선택 항목 메타데이터를 항상 포함하고 해당 항목 자체 문서를 우선 확보.
- 주요 주장별 인용, 실제 인용 문서만 표시, 근거 부족 시 보류.
- 게임 엔진은 가상 실행·복구 판정, RAG는 코칭 담당.
- 코치 입력에 숨겨진 faults·answerId·solutionPath·전체 state를 포함하지 않음.
- 문서 근거와 실습에서 관찰한 사실을 구분.
- 필수 F2001~F2012와 NF2001~NF2007 우선, 선택 심화 F2013/F2015.
- 상세화할 실습 3개와 신규 환경 1개는 제안 범위. 새 환경보다 필수 기능 우선.

## 상태 관리 규칙

설계 완료와 실행 통과를 구분한다. 시험하지 않은 항목을 통과 처리하지 않는다. 작업 단위 종료 시 TASKS/HANDOFF를 갱신하고 변경 파일·실제 시험 명령/결과·다음 작업을 기록한다. 한도가 모두 소진되기 전에도 기능 하나를 마칠 때마다 갱신한다.
